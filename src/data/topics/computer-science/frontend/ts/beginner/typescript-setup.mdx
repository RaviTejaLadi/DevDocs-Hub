# TypeScript Setup

## Definition

TypeScript is a superset of JavaScript that adds static typing and compile-time
checks.

## Install

```bash
npm install -D typescript
```

## Initialize Project

```bash
npx tsc --init
```

## Compile TypeScript

```bash
npx tsc
```

## Run TS File Directly

```bash
npm install -D ts-node
```

```bash
npx ts-node index.ts
```

## Interview Angle

- Explain **why teams use TypeScript**: safer refactors, better IDE
  autocomplete, and fewer runtime bugs.
- Mention that TypeScript checks happen at **build time**, not runtime.

## Production Setup Checklist

```bash
npm install -D typescript ts-node @types/node
```

```json
{
  "scripts": {
    "typecheck": "tsc --noEmit",
    "build": "tsc -p tsconfig.json",
    "dev": "ts-node src/index.ts"
  }
}
```

## Quick Reference

| Step | What to verify |
|---|---|
| Prerequisites | Runtime, version, permissions, and required tools. |
| Install | Use the documented package or installer for the platform. |
| Verify | Run a version/help command or a minimal program. |
| Troubleshoot | Check PATH, permissions, network, and version mismatches. |

## Environment Compatibility

Check the operating system, runtime version, architecture, shell, permissions, and package-manager version before following an installation command. The same command can behave differently across platforms. Record the exact version that worked so another developer can reproduce the environment.

## Verification in a Real Project

A successful version command proves that a binary is available, but it does not prove that the project can use it. Run a minimal project-level command as well. Confirm that the expected dependency is resolved, configuration is loaded, and the application can start without relying on an accidental global installation.

## Troubleshooting Logic

Change one variable at a time. A command-not-found error usually points to installation or PATH. A version error suggests an incompatible runtime. A permission error points to the account or filesystem. A network error points to registry, proxy, DNS, or firewall configuration. This classification is faster than reinstalling everything.

## Reproducibility Notes

A reliable setup should be repeatable on another machine. Keep installation steps close to the project documentation, pin important dependency versions, and distinguish required configuration from optional personal preferences. When the toolchain changes, update the verification step as well as the installation command. This makes setup failures easier to diagnose because you can compare the environment with a known working state.

Before considering **TypeScript Setup** revised, make sure you can state the definition without relying on the example, explain the mechanism in the correct order, and predict what happens when one important input or assumption changes. Then check one boundary case and one practical use case. The example should support the explanation rather than replace it. When a result is surprising, inspect the rule that produced it and verify the relevant precondition. This approach is more reliable than memorising a code snippet, formula, command, or interview answer because the same reasoning can be applied to a new problem. For technical topics, also distinguish what is guaranteed by the language, library, protocol, or mathematical rule from what is merely a common convention. That distinction helps you choose the correct solution when the context changes.
