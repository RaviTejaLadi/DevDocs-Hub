# 🚫 .gitignore

Not every file in your project folder belongs in your repository. System logs,
temporary build files, secret API keys, and massive dependency folders (like
`node_modules`) should never be tracked. To stop Git from watching them, we use
a special file called `.gitignore`. 📥

---

## What is a .gitignore file?

A `.gitignore` file is a plain text file placed directly in the root directory
of your repository. It tells Git: _"Hey, ignore any files or folders that match
these specific patterns."_

Once a file pattern is listed inside your `.gitignore`, Git will completely look
past it. It won't show up as an untracked file when you run `git status`, and it
won't be bundled when you run `git add .`.

## Matching Patterns & Rules

You can use specific rules and wildcards to tell Git exactly what to ignore.
Here is a breakdown of the most common syntax formatting rules:

// Example demonstrating 🚫 .gitignore.
```text

## Ignore a specific file by its exact name
secrets.env

## Ignore a folder and everything inside it
node_modules/
dist/

## Ignore all files ending with a specific extension (using a wildcard )
*.log
*.tmp

## Ignore all .mp4 files inside a specific directory
videos/*.mp4

## Exception: Ignore all .log files EXCEPT important.log
!important.log

```

## 🛠 Creating a .gitignore in Action

Let's look at how to set up and verify a standard `.gitignore` file inside a
brand new web project:

# Basic example showing the core idea.
```bash
// 1. Create your .gitignore file at the root of your project
touch .gitignore

// 2. Add files or folders you want to exclude
echo "node_modules/" >> .gitignore
echo ".env" >> .gitignore

// 3. Create a fake secret file to verify it works
touch .env

// 4. Run status - Git will see '.gitignore' but will NOT see '.env'
git status

> ⚠️ **The Golden Rule:** The `.gitignore` file only prevents **untracked**
> files from being added. If you have already committed a file and _then_ add it
> to your `.gitignore`, Git will continue tracking it! To fix this and stop
> tracking a file that was accidentally committed, you must manually remove it
> from Git's index using `git rm --cached <file>`.
