# Documents & Collections

**Documents & Collections** is easiest to learn by connecting each operation to an input, an action, and a result. Think of an API as a set of tools on a workbench: each method has a clear job, a defined input, and rules about whether it changes the original value.

## What It Provides

Start by identifying the data type or object this topic operates on, then list the operations it supports. Separate methods that return a new value from methods that mutate existing state. That distinction prevents a common revision mistake: assuming every method changes the original data.

## Core Operations

Group the operations by purpose instead of memorising them as an unrelated list. Typical groups are inspection, transformation, searching, insertion or deletion, and conversion. For each method, know its parameters, return value, mutation behaviour, and what happens for empty input.

### Small Example

// Basic example using a small input so the result is easy to verify.
```javascript
const values = [10, 20, 30];
const result = values.map(value => value / 10);
console.log(result);
```

## Real-World Use

The same operation becomes more useful when combined with validation and application logic. For example, a data transformation often needs to ignore invalid records, preserve the source data, or produce a predictable fallback.

// Realistic example with an explicit edge-case check.
```javascript
const prices = [120, null, 80, 200];
const validPrices = prices.filter(price => typeof price === 'number');
const totals = validPrices.map(price => price * 1.18);
console.log(totals);
```

## Common Mistakes

- Confusing mutation with returning a new value.
- Ignoring the callback parameters supplied by an API.
- Forgetting empty input and null-like values.
- Choosing a method because its name sounds right without checking its return value.

## Quick Reference

| Area | What to remember |
|---|---|
| Input | Know accepted data and edge cases. |
| Operation | Know exactly what the method does. |
| Return | Check the resulting type and value. |
| Mutation | Know whether the original object changes. |

## Return Values and Mutation

For every method, check what it returns and whether it mutates the original value. A transformation method commonly returns a new collection, while a mutating method changes the receiver. Knowing this difference prevents subtle bugs when the same data is reused in several parts of an application.

## Edge Cases Worth Testing

Test an empty collection, one element, duplicate values, invalid values, and a larger realistic input. Also check “not found” results and callback behavior for falsey values. Similar method names can have different return types or mutation rules, so verify them instead of relying on memory.

## Choosing the Right Operation

Choose an operation by intent. Use a filtering operation when you need a subset, a mapping operation when every item becomes a new value, a reduction when many values become one result, and a search operation when you only need the first matching item. Clear intent makes code easier to review and maintain.

## API Selection Notes

Choose an operation by the result you need, not by the shortest syntax. Check whether it preserves the original value, what it returns when nothing matches, and whether callbacks receive an index or the containing collection. For APIs used inside hot paths, also consider the number of passes over the data and temporary allocations. A clear method choice often communicates intent better than a manual loop, but only when the semantics match the requirement.
