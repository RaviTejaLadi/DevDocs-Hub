# DSA Interview Preparation Guide

A focused plan for revising data structures and algorithms before coding
interviews — without burning out on endless problem lists.

## Start with the fundamentals

Before jumping into LeetCode hard problems, make sure you can explain these
clearly in your own words:

- **Time and space complexity** — Big O for common operations on arrays, hash
  maps, trees, and graphs
- **Core structures** — arrays, strings, linked lists, stacks, queues, hash
  tables, trees, heaps, graphs
- **Key patterns** — two pointers, sliding window, binary search, BFS/DFS,
  recursion, dynamic programming

If any of these feel shaky, spend a day revisiting concepts before adding more
problems.

## A practical 4-week revision plan

### Week 1 — Linear structures & hashing

Focus on arrays, strings, hash maps, and two-pointer techniques. Aim for 2–3
problems per day with full write-ups of your approach.

### Week 2 — Trees, stacks & queues

Practice tree traversals (in-order, pre-order, level-order), stack-based
problems, and monotonic stack patterns.

### Week 3 — Graphs & advanced patterns

Work through BFS/DFS, topological sort, union-find, and introductory DP (1D
problems first).

### Week 4 — Mock interviews & weak spots

Revisit problems you got wrong. Do timed mocks (45 minutes, 1–2 problems).
Practice thinking aloud.

## How to approach each problem

1. **Clarify** — Ask about input size, edge cases, and expected output format
2. **Brute force first** — State the naive solution and its complexity
3. **Optimize** — Look for patterns: can hashing, sorting, or a two-pointer
   approach help?
4. **Code** — Write clean, readable code with meaningful variable names
5. **Test** — Walk through examples, including edge cases

## Common mistakes to avoid

- Grinding hundreds of problems without reviewing mistakes
- Skipping complexity analysis in your explanation
- Jumping to code before stating your approach
- Ignoring edge cases (empty input, single element, duplicates)

## Final checklist before interview day

- [ ] Can explain Big O for your top 10 solved problems
- [ ] Comfortable with at least one problem from each major pattern
- [ ] Practiced talking through your thought process out loud
- [ ] Reviewed 3–5 problems you previously got wrong

Good luck — consistency beats cramming.
